# Architecture Rules

The binding rules for this codebase. The orchestrator enforces them; every
agent follows them. When code conflicts with a rule, the rule wins.

## 1. Backend layering

Strict one-way dependency. An arrow means "may import / call".

```
api  →  service  →  repository  →  model
```

| Layer | May depend on | Must NOT |
|-------|---------------|----------|
| `api/` | `schemas`, `services` | hold business logic, touch the ORM |
| `services/` | `repositories`, `domain`, `integrations`, `schemas` | build HTTP responses, run raw SQL |
| `repositories/` | `models`, the DB session | hold business rules |
| `models/` | SQLAlchemy only | import services / api |
| `schemas/` | Pydantic only | import ORM models |

- Dependencies never point backward (a repository must not import a service).
- The SQLAlchemy session is touched **only** in `repositories/`.
- The **service** owns the transaction boundary — it calls `db.commit()`.

## 2. API conventions

- All endpoints are versioned under `/api/v1`.
- Endpoints are thin: validate input, call one service method, return a schema.
- Errors are raised as `AppError` subclasses from `app/core/exceptions.py`
  and serialized to a single envelope:
  ```json
  { "error": { "code": "...", "message": "...", "details": {} } }
  ```
- Pagination uses `PaginationParams` + `Page[T]` from `app/schemas/common.py`.
- Auth: `Depends(get_current_user)` for protected routes,
  `Depends(require_admin)` for admin-only routes.

## 3. Database

- Schema changes go through **Alembic** migrations. Never
  `Base.metadata.create_all()` for schema evolution.
- Autogenerated migrations are **reviewed before applying** — autogenerate
  misses server defaults, enum changes, and renames.
- Every foreign key and common filter column is indexed.
- Every model uses `IDMixin` + `TimestampMixin`.
- New models are registered in `app/db/base.py` so autogenerate sees them.

## 4. Frontend

- Feature-sliced: each feature folder owns its `api.js`, `hooks.js`,
  `store.js`, and `components/`.
- `pages/` compose features and hold routing — not data logic.
- All HTTP goes through `services/apiClient.js`. No raw `axios`/`fetch`.
- Server state → TanStack Query. Client/UI state → Zustand. No duplication
  of server data into Zustand.

## Frontend Performance Rules

- Use lazy loading
- Route-based code splitting
- Avoid large client bundles
- Optimize animations
- Use image optimization

## UI Standards

- Modern 2026 ecommerce UI
- Consistent spacing system
- Reusable design components
- Mobile-first design
- Accessibility support

This improves AI UI quality MASSIVELY.

## 5. Configuration & secrets

- All config is environment-driven, read through Pydantic `Settings`
  (`app/core/config.py`). No `os.environ` scattered through the code.
- Secrets live in gitignored `.env` files. Only `.env.example` is committed.
- Never hard-code credentials, keys, or hosts in source.

## 6. Docker

- Multi-stage builds; slim runtime; non-root user; `HEALTHCHECK` present.
- Exactly ONE compose file (`docker-compose.yml` = production, pulls GHCR
  images) and ONE workflow (`.github/workflows/cicd.yml`). Never add overlays.
- Local dev runs natively (uvicorn + vite); CI uses GH Actions `services:`.
- nginx, baked into the frontend image, is the single public entrypoint.

## 7. Testing

- Business logic (`services/`) carries unit tests.
- Cross-layer behaviour carries integration tests against a real database.
- Critical flows (auth, checkout) carry an e2e test.

## 8. Change safety

- Risky or irreversible actions — dropping tables, `docker compose down -v`,
  force operations, deleting branches — require explicit user confirmation.
- Prefer fixing root causes over bypassing checks.

## Definition of done (any feature)

- [ ] Architecture layering respected
- [ ] Schema changes have a reviewed migration
- [ ] API versioned, errors use the envelope
- [ ] Tests added and green
- [ ] Verified end-to-end against a running stack
- [ ] `current-task.md` handoff log updated
