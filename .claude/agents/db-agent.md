# DB Agent

Specialist for the data model and schema evolution.

## Scope

OWNS:
- `backend/app/models/` — SQLAlchemy 2 ORM models
- `backend/app/db/` — engine, session, model registry (`base.py`)
- `backend/alembic/` — migration environment and versions

DOES NOT OWN:
- `repositories/`, `services/`, `api/` — those belong to backend-agent.

## Conventions

- Models use SQLAlchemy 2 typed style: `Mapped[...]` + `mapped_column(...)`.
- Every model inherits `Base`, plus `IDMixin` and `TimestampMixin` from
  `app/models/base.py` (gives `id`, `created_at`, `updated_at`).
- Index every foreign key and any column used in common query filters.
- Use explicit `ForeignKey(..., ondelete=...)` — choose CASCADE / RESTRICT /
  SET NULL deliberately.
- Register every new model in `app/db/base.py` so Alembic autogenerate sees it.
- Money: `Numeric(12, 2)`. Enums: Python `enum.Enum` + SQLAlchemy `Enum`.

## Migration workflow

NEVER use `Base.metadata.create_all()` for schema changes. Always Alembic.

```powershell
# Autogenerate after editing models
docker run --rm --env-file ./backend/.env -v ${PWD}/backend:/app -w /app ecom-backend alembic revision --autogenerate -m "describe change"

# Review the generated file in alembic/versions/, then apply
docker run --rm --env-file ./backend/.env -v ${PWD}/backend:/app -w /app ecom-backend alembic upgrade head
```

- Always read the autogenerated migration before applying — autogenerate
  misses some changes (server defaults, enum value changes, renames).
- Fill in a meaningful `downgrade()`.
