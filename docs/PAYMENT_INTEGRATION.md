## 1. Architecture & mental model

- One endpoint, **`POST /checkout`**, creates a `PENDING` order (reserving stock) and — for prepaid — asks a **payment provider** for a **redirect URL**. The browser is sent there.
- The provider confirms later via a **signed webhook** (server-to-server), or we **poll** it when the customer returns. That moves the order `PENDING → PAID` (success) or `PENDING → CANCELLED` (failure/cancel).
- The link between us and the provider is the **merchant transaction id (`mtid`)**, stored on `orders.payment_intent_id`. The return page, webhook, and status poll all look the order up by it.
- Gateways are **admin-configured rows** in `payment_methods` (26 catalogued, **7 implemented**). Credentials are **Fernet-encrypted** at rest. Switching/reconfiguring needs **no redeploy** — the factory builds a fresh provider per request.
- Three payment methods: **`prepaid`** (full charge), **`cod`** (no gateway, paid on delivery), **`split_cod`** (gateway charges a prepaid portion, carrier collects the rest).

```
  Browser ──POST /checkout──▶ PaymentService.checkout()
     │                          ├─ resolve address, build PENDING order, reserve stock
     │                          ├─ factory → provider.initiate() ──▶ gateway
     │ ◀──── redirect_url ──────┘
     ▼ window.location.assign
  Gateway hosted page ──pays──▶ gateway host
     │                              │ signed webhook (S2S)
     │ redirect back               ▼
     ▼                       POST /payments/webhook/{gw} → verify → parse → _apply_status
  /payments/return?mtid=… ──poll every 1.5s──▶ GET /payments/{mtid}/status
     │                                            (also live-polls provider if still PENDING)
     ▼ success / failure screen
```

## 6. End-to-end flows

All three live in `PaymentService.checkout()` (`services/payment_service.py:66`).

### 6.1 Prepaid (default)
1. `_resolve_shipping_address` + `_resolve_billing_address` (saved id / inline / legacy free-text). Inline address optionally saved (`save_address`); never fails the sale on address-book errors.
2. `_build_order` (`:422`) validates products, **decrements stock** (reservation), computes:
   - subtotal, per-line tax (`compute_line_tax`),
   - shipping via authoritative `ShippingService.rate_quote` (never trusted from client; flaky carrier → 0 + log),
   - coupon discount (`CouponService.validate`),
   - per-instrument discount on `subtotal+tax` (only for prepaid/split, validated enabled),
   - free-shipping threshold override (`shipping.free_threshold`, prepaid/split only),
   - `total = subtotal + tax + shipping + cod_surcharge − discount − payment_discount`.
3. `mtid = _new_mtid()`; `order.payment_intent_id = mtid`; `add` + `flush` (id assigned), **no commit yet**.
4. `provider = get_payment_provider(db, data.gateway_code)`; `order.gateway_code = provider.name`; `provider.initiate(InitiateRequest(...))`; `order.payment_provider_ref = initiate.provider_transaction_id`.
5. On `initiate` exception → `db.rollback()` (returns reserved stock) and raise. On success → `db.commit()`. Returns `(order, mtid, initiate.redirect_url)`.
6. SPA `window.location.assign(redirect_url)`. Gateway pays → webhook → `_apply_status` → PAID/CANCELLED. Browser returns to `PAYMENT_RETURN_URL?mtid=…`; SPA polls status.

### 6.2 COD (`:108`)
- No gateway call. `_enforce_cod_availability` re-runs the COD gate on the trusted cart+pincode (client cannot bypass). `_enforce_cod_otp_if_required` — when `cod.require_otp` (default **true**) the customer must have a verified OTP marker for `customer_phone`; the marker is **consumed** (next COD order needs a fresh OTP).
- COD surcharge added; `cod_balance = total`.
- `_mark_paid(order)` → status PAID, `paid_at`, record coupon usage, award loyalty, complete referral, clear cart. Commit. Then post-paid side effects (`order_paid` notification + optional auto-shipment).
- `redirect_url = {PAYMENT_RETURN_URL}?mtid={mtid}` so the SPA shows confirmation immediately.

### 6.3 Split COD (`:131`)
- `_enforce_cod_availability` runs. `prepaid_minor = (total − cod_balance) × 100`. If ≤ 0 → rollback + `ValidationError` ("re-select payment method").
- `provider.initiate(...)` with `amount_minor = prepaid_minor`. Order stays PENDING; the gateway webhook moves it to PAID (same path as prepaid).
- `cod_balance` is collected by the carrier via the `ShipmentRequest.cod_amount` hook in `ShippingService`. The prepaid portion is snapshotted at build time (`CodService.split_prepaid_for(total)`) so an admin bumping the setting can't overcharge an in-flight order.

> `CheckoutResponse.amount_minor` (computed in `endpoints/payments.py:46`): **0** for COD, **prepaid portion** for split COD, **full total** for prepaid.

## 7. Provider contract (`base.py`)

```python
class PaymentStatus(str, Enum):  PENDING="pending"; SUCCESS="success"; FAILED="failed"

@dataclass class InitiateRequest:  order_id; user_id; amount_minor; currency;
                                    merchant_transaction_id; return_url; user_email=None; user_phone=None
@dataclass class InitiateResponse: redirect_url; provider_transaction_id=None; raw=None
@dataclass class StatusResponse:   merchant_transaction_id; status; provider_transaction_id=None;
                                    amount_minor=None; raw=None

class PaymentProvider(Protocol):
    name: str
    def initiate(req) -> InitiateResponse
    def fetch_status(mtid, provider_ref=None) -> StatusResponse
    def verify_webhook(body: bytes, signature: str | None) -> bool
    def parse_webhook(body: bytes) -> StatusResponse
```
Each provider raises its own `AppError` subclass with `code = "payment_provider_error"`. Constructors raise immediately if required credentials are absent.

## 8. Error surfacing

`base.py` (commit `01a3908`) turns generic "rejected" wrappers into the gateway's real reason:

- `extract_provider_error(response) -> (code, message)` — parses each gateway's documented error envelope:
  - Razorpay/Stripe: `{"error": {"code"|"type", "description"|"message"}}`
  - PayPal token: `{"error", "error_description"}`; PayPal Orders: `{"name", "message", "details":[{"issue","description"}]}`
  - Paystack: `{"status": false, "message", "code"?}`; Flutterwave: `{"status":"error","message"}`; PhonePe: `{"code","message"}`
  - Non-JSON body → `(None, None)`. Values trimmed, capped at 300 chars.
- `provider_rejection(error_cls, prefix, response) -> AppError` — message like `"Razorpay rejected the request: BAD_REQUEST_ERROR — amount is invalid"`, with `details={status, provider_code, provider_message}`.

Every provider's HTTP helper calls `provider_rejection(...)` in its `httpx.HTTPStatusError` branch; network errors raise a "Could not reach X." `AppError`. The SPA reads `err.response.data.error.message`.

## 9. Provider reference (all 7 implemented)

All providers use `httpx.Client(timeout=15.0)`. Amounts are sent in minor units unless noted.

### 9.1 PhonePe (`phonepe.py`) — Standard Checkout v1
- **Creds**: `merchant_id`, `salt_key` (secret), `salt_index` (default 1). Base URL by env: sandbox `https://api-preprod.phonepe.com/apis/pg-sandbox`, live `https://api.phonepe.com/apis/hermes` (from `factory._PHONEPE_BASE`). Callback URL = `settings.PAYMENT_WEBHOOK_URL`.
- **Signature** (`_sign`): `sha256(message + salt_key) + "###" + salt_index`.
  - initiate: sign `base64(payload) + "/pg/v1/pay"`; status: sign the endpoint path; webhook: sign the base64 `response` string.
- **initiate**: `POST /pg/v1/pay`, body `{"request": base64(payload)}`, header `X-VERIFY`. Payload: `merchantId, merchantTransactionId, merchantUserId="USER{id}", amount, redirectUrl, redirectMode="REDIRECT", callbackUrl, paymentInstrument={"type":"PAY_PAGE"}` (+`mobileNumber` if phone). Redirect from `data.instrumentResponse.redirectInfo.url`; `provider_transaction_id = data.transactionId`.
- **fetch_status**: `GET /pg/v1/status/{merchant_id}/{mtid}`, headers `X-VERIFY` + `X-MERCHANT-ID`.
- **status mapping** (`_to_status`): `code == PAYMENT_SUCCESS` or `data.state == COMPLETED` → SUCCESS; `code ∈ {PAYMENT_ERROR, PAYMENT_DECLINED, PAYMENT_CANCELLED, TIMED_OUT, TRANSACTION_NOT_FOUND}` → FAILED; else PENDING. `amount_minor = data.amount`.
- **webhook**: body `{"response": base64(json)}`; `verify_webhook` re-signs the base64 string and `compare_digest` vs `X-VERIFY`. `parse_webhook` decodes and reads `data.merchantTransactionId`.

### 9.2 Razorpay (`razorpay.py`) — Payment Links
- **Creds**: `key_id`, `key_secret` (HTTP basic auth), `webhook_secret` (optional). Base `https://api.razorpay.com/v1`.
- **initiate**: `POST /payment_links` `{amount, currency, reference_id=mtid, callback_url=return_url, callback_method="get"}`. Redirect = `short_url || url`; `provider_transaction_id = id`.
- **fetch_status**: needs `provider_ref`; without it → PENDING. `GET /payment_links/{ref}`; `paid`→SUCCESS (`amount_paid||amount`), `cancelled`/`expired`→FAILED, else PENDING.
- **webhook**: `X-Razorpay-Signature` = `HMAC-SHA256(webhook_secret, raw_body)` hex. `parse_webhook`: `event=="payment_link.paid"`→SUCCESS using `payload.payload.payment_link.entity.reference_id` as mtid.

### 9.3 Stripe (`stripe.py`) — Checkout Sessions
- **Creds**: `secret_key` (Bearer; required), `publishable_key`, `webhook_secret` (optional). Base `https://api.stripe.com/v1` (form-encoded).
- **initiate**: `POST /checkout/sessions` form: `mode=payment, client_reference_id=mtid, success_url=return_url+"&stripe=1", cancel_url=return_url+"&cancelled=1"`, single `line_items[0]` with `price_data.currency`, `unit_amount=amount_minor`, `product_data.name="Order {mtid}"`, `quantity=1`. Redirect = `url`; `provider_transaction_id = id`.
- **fetch_status**: needs `provider_ref`. `GET /checkout/sessions/{ref}`; `payment_status=="paid"`→SUCCESS (`amount_total`), `status=="expired"`→FAILED, else PENDING.
- **webhook**: `Stripe-Signature` `t=…,v1=…`; verify `HMAC-SHA256(webhook_secret, "{t}.{body}")` vs `v1`. `parse_webhook`: `checkout.session.completed`→SUCCESS (`amount_total`), `checkout.session.expired`→FAILED; mtid from `data.object.client_reference_id`.

### 9.4 PayPal (`paypal.py`) — Orders v2 (OAuth)
- **Creds**: `client_id`, `client_secret`. Base by env: sandbox `https://api-m.sandbox.paypal.com`, live `https://api-m.paypal.com`. OAuth token via `POST /v1/oauth2/token` (client-credentials).
- **initiate**: `POST /v2/checkout/orders` `{intent:"CAPTURE", purchase_units:[{custom_id=mtid, amount:{currency_code, value="{amount_minor/100:.2f}"}}], application_context:{return_url, cancel_url=return_url+"&cancelled=1", user_action:"PAY_NOW"}}`. Redirect = the `links[]` entry with `rel=="approve"`; `provider_transaction_id = id`.
- **fetch_status**: needs `provider_ref`. `GET /v2/checkout/orders/{ref}`; if `APPROVED` → **auto-capture** via `POST .../capture`; `COMPLETED`→SUCCESS (amount from `purchase_units[0].amount.value*100`), `VOIDED`→FAILED, else PENDING.
- **webhook**: **NOT USED** — `verify_webhook` always returns `False`; relies on return-page status polling + auto-capture. `parse_webhook` is a stub (would map `CHECKOUT.ORDER.COMPLETED`/`PAYMENT.CAPTURE.COMPLETED`→SUCCESS).

### 9.5 Paystack (`paystack.py`) — Transaction Initialize
- **Creds**: `secret_key` (Bearer; required), `public_key`. Base `https://api.paystack.co`.
- **initiate**: `POST /transaction/initialize` `{amount, currency, reference=mtid, callback_url=return_url, email=user_email||"customer@example.com"}`. Redirect = `data.authorization_url`; `provider_transaction_id = data.access_code`.
- **fetch_status**: `GET /transaction/verify/{mtid}` (verifies by reference = our mtid); `success`→SUCCESS (`data.amount`), `{failed,abandoned,reversed}`→FAILED, else PENDING.
- **webhook**: `x-paystack-signature` = `HMAC-SHA512(secret_key, raw_body)` hex. `parse_webhook`: `charge.success`→SUCCESS; mtid from `data.reference`.

### 9.6 Flutterwave (`flutterwave.py`) — Standard/Hosted v3
- **Creds**: `secret_key` (Bearer; required), `public_key`, `webhook_secret_hash` (optional). Base `https://api.flutterwave.com/v3`.
- **initiate**: `POST /payments` `{tx_ref=mtid, amount=str(amount_minor/100), currency, redirect_url=return_url, customer:{email}}`. Redirect = `data.link`; `provider_transaction_id = None`.
- **fetch_status**: `GET /transactions/verify_by_reference?tx_ref={mtid}`; `successful`→SUCCESS (`amount*100`), `failed`→FAILED, else PENDING.
- **webhook**: `verif-hash` header compared by **plain `compare_digest(webhook_secret_hash, signature)`** (NOT HMAC — correct per Flutterwave docs). `parse_webhook`: `data.status=="successful"`→SUCCESS, `"failed"`→FAILED; mtid from `data.tx_ref`.

### 9.7 Mock (`mock.py`) — local simulator
- **Creds**: none (`supports_environment=False`). Built from `FRONTEND_URL` + `REDIS_URL`.
- **initiate**: stores `{status:"pending", amount_minor, order_id}` in Redis (`payment:mock:{mtid}`, TTL 1h). Redirect = `{FRONTEND_URL}/payments/mock/{mtid}?return={return_url}&amount={amount_minor}`.
- **fetch_status**: reads the Redis record (PENDING if missing).
- **webhook**: `verify_webhook` always `True` (trusts in-network callers; **hard-disabled in production** at the route level). `parse_webhook`: body `{"merchant_transaction_id","action"}`; `approve`→SUCCESS, else FAILED; persists status back to Redis.

## 11. Factory & checkout resolution

**`factory.py`**
- `get_payment_provider(db, gateway_code=None)` → `PaymentMethodConfigService.resolve_for_checkout(gateway_code)` → `credentials_for(code)` → `_build_provider(row, creds)`. Fresh instance per call; no caching.
- `get_provider_for_order(db, order)` → uses `order.gateway_code`, else default (legacy NULL rows).
- `_build_provider` maps `gateway_code` → provider constructor with creds (PhonePe base URL chosen from env). Unknown/unimplemented → logs error, falls back to mock.

**`resolve_for_checkout(gateway_code)`** (`payment_method_config_service.py:106`)
- **Explicit code**: row must exist, `implemented`, `enabled`, and have **no missing required fields** — otherwise a customer-friendly `ValidationError` ("not available / not supported / not currently enabled / not fully configured").
- **`None`**: pick the **lowest `sort_order`** enabled row that is implemented + ready (mock is always ready when enabled).
- **Fallback**: enabled `mock` row, else `ValidationError("No payment gateway is currently available…")`.
- **Readiness** = `_missing_required_fields(gw, creds)` empty, where a field is missing if `required and not creds.get(key, "").strip()`.

## 12. Admin config service rules

**`update(code, payload)`** (`payment_method_config_service.py:43`):
- `environment` set directly if provided.
- **Credentials = partial merge**: `key=""` deletes the key; **unknown keys** (not in the registry for this gateway) → `ValidationError`. The merged dict is re-encrypted (`encrypt_secret(json.dumps(...))`), or stored as `""` when empty.
- **`enabled=True`** requires `implemented` and **no missing required fields** after the merge, else `ValidationError`.
- Commits and returns `PaymentMethodRead`.

**`_to_read`**: secret fields never expose `value` (only `set: bool`); non-secret fields return their plaintext value. `ready` = all required present. Unknown DB code → minimal `implemented=False, ready=False` representation.

`_decrypt_creds` swallows decrypt failures (e.g. after `SECRET_KEY` rotation) and logs + treats as empty.

## 14. Webhooks & signature verification

| gateway | header | verification |
|---|---|---|
| phonepe | `X-VERIFY` | `sha256(base64body + salt_key) + "###" + salt_index`, constant-time compare |
| razorpay | `X-Razorpay-Signature` | `HMAC-SHA256(webhook_secret, body)` |
| stripe | `Stripe-Signature` (`t=,v1=`) | `HMAC-SHA256(webhook_secret, "{t}.{body}")` vs `v1` |
| paystack | `x-paystack-signature` | `HMAC-SHA512(secret_key, body)` |
| flutterwave | `verif-hash` | plain `compare_digest(secret_hash, header)` (not HMAC) |
| paypal | — | **not used**; status polling only (`verify_webhook` → False) |
| mock | — | always trusts; disabled in prod |

**Flow** (`PaymentService.handle_webhook`): `get_payment_provider(db, code)` → `verify_webhook` (False → `403 Invalid payment signature`) → `parse_webhook` → `_order_for_mtid` → `_apply_status(order, status, gateway_amount_minor)`.

The generic route (`endpoints/payments.py:128`) first checks the gateway row exists, is implemented, and is enabled, then picks the right signature header before delegating.

## 15. Correctness guarantees

`_apply_status` (`payment_service.py:585`):
- **Idempotent**: only `PENDING` orders move; re-delivered webhooks on a terminal order are a no-op (webhooks can fire twice).
- **Amount-tampering block**: on SUCCESS, if `gateway_amount_minor` is provided and ≠ `round(total_amount × 100)`, the order is **left PENDING** and an error is logged — it is **not** marked PAID. Blocks amount tampering and cross-order webhook replay.
- **FAILED** → status CANCELLED + `_restore_stock` (give reserved units back).
- **Side effects after commit**: `_send_notification("order_paid")` + `_maybe_auto_push_shipment` run only after the DB commit, so no "paid" email goes out for an unsaved row. All side effects (loyalty, referral, coupon usage, cart clear, notifications, shipment) are wrapped so a flaky downstream never rolls back the payment.
- **Stock** is reserved (decremented) at checkout and restored only on failure.
- **Status polling** (`get_status`): a still-PENDING order triggers a live `provider.fetch_status()`; provider errors are caught/logged so the poll never 500s.

## 22. Gotchas & known issues

- **Two similarly-named services**: `payment_methods_service.py` = instrument toggles/discounts; `payment_method_config_service.py` = gateway config. Don't confuse them.
- **Legacy split-brain (fixed)**: `mark_mock_decision` / `mock_webhook` used to read the deprecated `PaymentGatewayConfig` "active provider" row, which the factory no longer consults — that let a real order be mock-settled or a genuine mock order be blocked. Authorization is now **per-order**: a mock settle is allowed only if `order.gateway_code == "mock"` (the change currently uncommitted in `payments.py` + `payment_service.py`).
- **PayPal has no webhook** — confirmation depends entirely on the return-page status poll + auto-capture. If the customer abandons before returning, reconciliation waits for the next poll.
- **Flutterwave verify is a plain hash compare**, not HMAC (correct per their docs).
- **`SECRET_KEY` rotation wipes all stored gateway credentials** — re-enter them in admin afterward.
- **Mock webhook is unsigned** and trusts callers — hard-disabled in production.
- **`fetch_status` needs `payment_provider_ref`** for Razorpay/Stripe/PayPal; PhonePe/Paystack/Flutterwave verify by our `mtid`.
- Project memory: PhonePe creds may need re-entry after edits; PayPal webhook intentionally off; the 2026-06 security audit (35 vulns, ~65% remediated, paused) may have outstanding payment items, and the prod DB credential rotation/history-purge was still pending.

## 23. How to add a new gateway

1. **Registry** (`registry.py`): set `implemented=True` on the `GatewayDef` (or add one) with its credential `fields`.
2. **Provider class** (`integrations/payments/<code>.py`): implement `initiate / fetch_status / verify_webhook / parse_webhook`; constructor raises if required creds missing; use `provider_rejection(...)` in the `httpx.HTTPStatusError` branch.
3. **Factory** (`factory.py:_build_provider`): add `if code == "<code>": return XProvider(**creds...)`.
4. **Webhook header** (`endpoints/payments.py` generic route): add the gateway's signature header to the selection block.
5. **Migration**: ensure a `payment_methods` row exists (the seed migration inserts all 26; new gateways need a follow-up migration).
6. Admin enables it in `/admin/payment-methods`, enters creds, sets sandbox/live — no redeploy.
7. Tests + verify the full redirect→webhook→status loop against the mock first.

## 24. Local dev & testing

- Default dev gateway is **mock** (seeded `sort_order` 99). It's seeded enabled but may be disabled in a DB where a real gateway was configured — enable it (admin UI or `PaymentMethodConfigService.update("mock", PaymentMethodUpdate(enabled=True))`) before relying on it. Checkout then redirects to `/payments/mock/{mtid}`; Approve/Decline drives `_apply_status` exactly like a real webhook (state in Redis).
- Backend changes need a **restart**; frontend a **rebuild** (Windows bind-mount watch unreliable). MySQL host port is **3307** in this environment.
- High-value tests: amount-mismatch rejection (stays PENDING), idempotent re-delivery, signature failure → 403, COD OTP gate + consume, split-COD prepaid math + degenerate guard, stock restore on failure, `resolve_for_checkout` gates (disabled/unimplemented/missing creds), `SECRET_KEY` rotation → not-ready.
